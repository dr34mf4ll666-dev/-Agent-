# 客户证券分析前台

## 1. 它给谁使用

客户前台是项目的成果展示面，不是工程验收面。访问者只需要选择研究标的和数据版本，就能看到一份接近分析 App 的中文报告；页面不会要求访问者理解 Harness、Graph、Checkpoint、测试脚本或项目目录。

启动项目后访问：

```text
http://127.0.0.1:8765/
```

团队需要查看 A–D 技术能力、完整 trace 或逐项运行功能时，再进入 `/admin`。

## 2. 页面展示什么

- 最新价、涨跌幅、数据时间和数据来源数量；
- 同一冻结行情生成的日 K/周 K、20/40/60 根显示区间、SMA5、SMA20、成交量，以及支撑位、当前参考价和压力位；
- 综合观点、证据一致性、综合得分和研究仓位上限；
- 技术、基本面、行业、宏观四个研究维度；
- “研究天平”以 0 分为中轴对比四个 Agent 的方向和强度，并标出主要支持、主要风险与观点分歧；
- 支持因素与需要留意的风险因素；
- 可手动触发的动态多空辩论，逐轮展示 Bull/Bear 观点和回应；
- 研究价格区间、预计单笔风险、收益风险比和风控状态；
- DeepSeek 或本地安全解释生成的通俗说明。
- 本次分析统一使用的 `snapshot_id`、统一数据时点，以及每类数据的主源、备用源、缓存或缺失状态。
- “最近分析”历史卡片，以及当时任务状态、数据版本和报告版本；点击可重新打开冻结报告，也可经二次确认删除单条或清空全部历史。

页面只展示 C3 完整金融 Graph 已经产出的结构化结果。它不是另一套独立分析逻辑，因此客户看到的分数、价格区间和风险边界与后台验收使用同一数据来源。

P2 会先冻结 14 类唯一数据请求，再让四个 Agent、C3 Graph、K 线和最终报告消费同一快照。页面的“统一数据快照”区域让客户直接看到本次来源健康；Graph 完成后不再为图表重复抓日线。失败重试和服务重启恢复会继续使用原快照，不把新旧两批数据拼进同一报告。

P3 在任务成功前把这份冻结结果原子写入 SQLite。页面重新打开历史卡片时只读取数据库里的同一份报告、同一个 `report_id` 和 `snapshot_id`，不会重新访问外部数据源、重新执行 Graph 或改变结论。DeepSeek 解读只追加模型、Token 和耗时元数据，不保存 Key 或 Prompt。

P4 把客户报告分成两种阅读深度。首次使用默认普通版，以“结论摘要、主要依据、主要风险、关注区间”呈现，同时隐藏 K 线、分数、模型解释和专业风控指标；用户主动切换专业版后，才显示四个 Agent、17 个真实节点、指标、来源、评分与风控细节。选择保存在浏览器里，但两种视图都由服务器从同一冻结报告生成，切换不会创建任务、重新取数、运行 Graph 或调用模型。

专业版 K 线可以切换日线/周线和 20/40/60 根区间，独立开关 SMA5、SMA20 与成交量。鼠标移动会显示十字线和 OHLCV，键盘左右方向键也能逐根查看。四个 Agent 卡片可展开核心指标、来源和证据时间；完成、跳过等状态同时使用文字，不只依赖颜色。专业版仍是客户研究界面，不展示 Harness 配置、Checkpoint 文件或原始日志。

## 3. 两种数据版本

“已验证快照”使用仓库内固定样本，结果稳定、无需联网，适合答辩和功能展示。“最新数据”通过项目已有金融 Data Hub 读取真实只读数据，可能受网络、数据源或 Token 配置影响。

当前客户股票池由版本化证券主数据维护，开放 21 只已经通过验证的沪深 A 股，覆盖上交所和深交所，包含 20 只银行股和第一个非银行标的五粮液（`sz000858`）。前台可以按名称/代码搜索和按行业筛选；客户看到的行业是主数据中的稳定分类，调用数据源时使用的分析行业标签另行保存。

只有平安银行 `sz000001` 同时拥有一套完整、可独立复现的离线四维样本，因此它支持“已验证快照”和“最新数据”。其余 20 只股票只支持“最新数据”；用户选择这些股票时，页面会自动切换模式并禁用快照按钮，不会拿平安银行的离线财务数据冒充其他股票。

平安银行离线快照中的行业 Agent 样本范围仍是“玻璃行业”，页面会明确展示该范围，不能把它误解为平安银行所属行业结论。

证券主数据的字段、验证状态和真实跨行业验收见 [`security-master.md`](security-master.md)。

## 4. DeepSeek 的作用

运行 `D:\Anaconda\python.exe Scripts\run_dashboard.py` 时，如果当前进程没有 `DEEPSEEK_API_KEY`，终端会隐藏提示输入。输入 Key 后，前台会把完整结构化分析交给项目已有 Model Gateway，并要求 DeepSeek 返回固定 JSON 结构：标题、通俗解释和风险提示；直接回车则保持本地固定格式。Key 只在本次运行中有效，不会写入项目文件。

DeepSeek 只负责“把已有结果讲清楚”。技术指标、财务数值、综合评分、仓位、止损止盈和预计风险仍由确定性代码计算。模型不能覆盖这些结果，不能保证收益，也不能声称已经下单。没有 Key 时，页面自动使用本地安全解释，核心分析功能不受影响。

“生成动态多空解读”同样复用 Model Gateway，但不会把浏览器提交的报告直接当作事实。服务器只接受本次分析生成的短期 `analysis_id`，从内存取回原始四 Agent 报告，再给模型一份编号化证据目录。模型只能选择证据编号并生成 Claim 和 Reasoning；程序随后还原真实路径、数值、来源和 `as_of`，检查双方证据覆盖、轮次关系、虚构数字和违规措辞。候选不合规时最多尝试两次，之后自动退回固定辩论。该按钮必须由用户主动点击，普通股票分析不会因此增加 Token 消耗。

当前已通过 Mock 离线测试、无 Key 页面降级验证，以及“启动时隐藏输入 Key 后三类 DeepSeek 组件同时启用”的进程级验证。项目还提供固定动态辩论评测集，重复比较模板与动态模式的证据有效率、观点多样性、正反平衡、重试、降级、耗时、Token 和稳定性；真实 DeepSeek 固定评测已由用户进程完成 4 次受控调用并通过质量门禁，逐次结果保存在 `.runtime/llm-evaluation/deepseek-fixed-v1.json`。

## 5. 安全边界

客户报告固定保留以下边界：

```text
simulation_only=true
order_created=false
real_trading_allowed=false
```

页面中的“仓位上限”“预计单笔风险”和“研究价格区间”用于教学、研究和模拟风险说明，不构成投资建议，也不会连接券商。

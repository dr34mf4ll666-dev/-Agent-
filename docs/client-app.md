# 客户证券分析前台

## 1. 它给谁使用

客户前台是项目的成果展示面，不是工程验收面。访问者只需要选择研究标的和数据版本，就能看到一份接近分析 App 的中文报告；页面不会要求访问者理解 Harness、Graph、Checkpoint、测试脚本或项目目录。

启动项目后访问：

```text
http://127.0.0.1:8765/
```

团队需要查看 A–D 技术能力、完整 trace 或逐项运行功能时，再进入 `/admin`。

## 2. 页面展示什么

- 最新价、涨跌幅、数据时间和数据来源数量；
- 30 根日 K 线，以及支撑位、当前参考价和压力位；
- 综合观点、证据一致性、综合得分和研究仓位上限；
- 技术、基本面、行业、宏观四个研究维度；
- 支持因素与需要留意的风险因素；
- 研究价格区间、预计单笔风险、收益风险比和风控状态；
- DeepSeek 或本地安全解释生成的通俗说明。

页面只展示 C3 完整金融 Graph 已经产出的结构化结果。它不是另一套独立分析逻辑，因此客户看到的分数、价格区间和风险边界与后台验收使用同一数据来源。

## 3. 两种数据版本

“已验证快照”使用仓库内固定样本，结果稳定、无需联网，适合答辩和功能展示。“最新数据”通过项目已有金融 Data Hub 读取真实只读数据，可能受网络、数据源或 Token 配置影响。

当前客户股票池开放 20 只已经通过 C3 真实批量链路验证的银行股，覆盖上交所和深交所，包括平安、浦发、招商、兴业、工商、建设、农业、中国、交通、邮储、宁波等银行。所有股票的最新数据模式都使用数据源实际提供的“金融行业”范围。

只有平安银行 `sz000001` 同时拥有一套完整、可独立复现的离线四维样本，因此它支持“已验证快照”和“最新数据”。其余 19 只股票只支持“最新数据”；用户选择这些股票时，页面会自动切换模式并禁用快照按钮，不会拿平安银行的离线财务数据冒充其他股票。

平安银行离线快照中的行业 Agent 样本范围仍是“玻璃行业”，页面会明确展示该范围，不能把它误解为平安银行所属行业结论。

## 4. DeepSeek 的作用

设置 `DEEPSEEK_API_KEY` 后，前台会把完整结构化分析交给项目已有 Model Gateway，并要求 DeepSeek 返回固定 JSON 结构：标题、通俗解释和风险提示。

DeepSeek 只负责“把已有结果讲清楚”。技术指标、财务数值、综合评分、仓位、止损止盈和预计风险仍由确定性代码计算。模型不能覆盖这些结果，不能保证收益，也不能声称已经下单。没有 Key 时，页面自动使用本地安全解释，核心分析功能不受影响。

## 5. 安全边界

客户报告固定保留以下边界：

```text
simulation_only=true
order_created=false
real_trading_allowed=false
```

页面中的“仓位上限”“预计单笔风险”和“研究价格区间”用于教学、研究和模拟风险说明，不构成投资建议，也不会连接券商。

## 6. 验收

客户前台专项测试：

```powershell
D:\Anaconda\python.exe -m unittest tests.test_client_app tests.test_dashboard -v
```

完整产品验收：

```powershell
D:\Anaconda\python.exe Scripts\demo_product_acceptance.py
```

完整验收会检查 A–D 核心链路、客户页面资源、至少 20 只沪深股票、四个研究维度、至少 30 根 K 线、可读综合观点、风险区间、后台 18 个入口以及真实交易关闭。默认只在终端输出结果，不生成报告文件。

# 证券主数据与跨行业扩展

P9 已完成。它解决的是目录问题：以前客户前台的 20 只股票、行业名称和数据模式直接写在 `client_app.py`；现在由版本化的 [`security_master.v1.json`](../src/agent_platform/resources/security_master.v1.json) 统一描述。

## 1. 目录记录了什么

每条证券主数据包含：

- 证券代码、交易所、名称和上市状态；
- 面向客户的行业，例如“银行”“酿酒”“电力”；
- 数据源实际需要的分析行业标签，例如“金融行业”“酿酒行业”“电力行业”；
- 可用数据模式、来源、能力开关和快照状态；
- `verified` 与 `customer_visible` 两个状态。

`SecurityMasterRuntime` 是后端的稳定接口，负责读取、校验、搜索、按行业筛选和生成客户目录。旧的 `SECURITIES` 只是兼容视图，不再是数据源。新增证券只需增加一条经过校验的数据记录，不需要修改客户分析业务代码。

## 2. 客户前台能看到什么

研究入口现在提供：

- 名称或代码搜索；
- 行业筛选；
- 选项中直接显示交易所和行业；
- 目录版本、可研究数量和行业数量；
- 每个标的仍按自己的能力禁用不适用的数据模式。

当前正式目录为 22 只沪深 A 股：20 只银行股，加上五粮液（`sz000858`）和华银电力（`sh600744`）两个已经通过真实完整 Graph 验证的非银行标的。平安银行保留“已验证快照/最新数据”两种模式；两个非银行标的当前只开放最新只读数据，没有伪造离线快照。

## 3. 跨行业验证

真实验证命令：

```powershell
D:\Anaconda\python.exe Scripts\demo_security_master.py
D:\Anaconda\python.exe Scripts\demo_security_master.py --verify-non-bank
D:\Anaconda\python.exe Scripts\demo_security_master.py --verify-electric
```

第二条命令会调用已有的完整金融 Graph，验证五粮液的行情、基本面、行业、宏观、综合研判、Trader、条件路由和 Risk Manager。结果只打印到终端，不生成报告文件；真实交易仍关闭。

第三条命令用同一条真实只读完整 Graph 验证华银电力，并检查客户行业“电力”到数据源分析行业“电力行业”的字段映射。它同样只打印结果，不保存原始行情或报告文件；如果任一关键数据无法验证，华银电力不会被安全地加入正式目录。

这两次验证还补充了跨行业字段兼容：部分非银行财报把股东权益和资本开支写成不同的中文字段，确定性基本面计算现在会识别这些已确认的同义字段；电力行业同时有独立的产业链分类模板。LLM 不参与字段映射，也不能改写数值、评分、仓位和风控。

## 4. 状态边界

“数据源可用”不等于“标的已经进入客户目录”。只有真实完整链路通过后，记录才会同时标记 `verified=true` 和 `customer_visible=true`。尚未完成验证的候选记录可以保留在主数据文件中，但不能被客户搜索、分析或加入自选。
